# Сравнение с оригинальным paris-traceroute

Оригинал: [libparistraceroute](https://github.com/libparistraceroute/libparistraceroute),
коммит `9588da5` (ноябрь 2025), `paris-traceroute version 1.0`, собран из
исходников в Ubuntu 26.04 (WSL2, ядро 6.18) с отключённым `-Werror`: без этого
новые GCC его не собирают. Go-версия — v1.0.0 из этого репозитория. Обе
запускались от root на одной машине, 9 октября 2026.

## 1. Лабораторная сеть с балансировщиком

Сеть из Linux network namespaces (`test/lab/ecmp.sh`):

```
src --- r1 ==(ECMP на 3 пути, хеш по L4)== r2a | r2b | r2c --- r3 --- dst (10.0.9.2)
```

| Проверка | Оригинал | Go |
|---|---|---|
| paris UDP: маршрут до dst | 10.0.1.1 → 10.0.3.2 → 10.0.5.2 → 10.0.9.2 | тот же |
| paris UDP: все пробы хопа на одном пути | да | да |
| Одинаковый 5-tuple даёт одинаковый путь (16 портов источника) | — | 16 из 16 совпадают с оригиналом |
| paris ICMP | хопы 1–3, назначение не определено (`* * *` до конца) | хопы 1–4, назначение достигнуто |
| paris TCP | хопы 1–3, назначение не определено | хопы 1–4, назначение достигнуто |
| MDA UDP | 10.0.1.1 → {10.0.2.2, 10.0.3.2, 10.0.4.2} → 10.0.5.2 → 10.0.9.2 | тот же граф, 82 пробы |
| MDA TCP | не поддерживается | тот же граф |
| MDA ICMP | `Cannot set field 'flow_id'`, зависает до таймаута | работает (ядро Linux не балансирует ICMP по L4, путь один) |

Автотест `test/lab/ecmp.sh` с `ORIG=...`: 13 из 13 проверок пройдены.

## 2. Loopback

| Цель | Оригинал | Go |
|---|---|---|
| 127.0.0.1 UDP | достигнут | достигнут |
| 127.0.0.1 ICMP | `* * *` (не сопоставляет echo reply: `Can't retrieve tag from reply`) | достигнут |
| 127.0.0.1 TCP | `* * *` | достигнут |
| ::1 UDP | достигнут | достигнут |
| ::1 ICMP | `* * *` | достигнут |

## 3. Реальный интернет (WSL2 за двумя NAT: Hyper-V и домашний роутер)

| Цель | Оригинал | Go |
|---|---|---|
| 1.1.1.1 UDP | только хоп 1, дальше `* * *` | 10 хопов, назначение достигнуто |
| 1.1.1.1 ICMP | только хоп 1 | 10 хопов, назначение достигнуто |
| 1.1.1.1 TCP:443 | только хоп 1 | хопы 1–3 и 6, дальше ответы через NAT не проходят |
| 8.8.8.8 UDP / ICMP | только хоп 1 | 12 хопов (сеть Google режет часть ответов) |
| 1.1.1.1 MDA UDP | только хоп 1 | 256 проб, найдено 3 параллельных интерфейса на хопе 9, назначение достигнуто |
| 1.1.1.1 MDA ICMP | зависает (`Cannot set field 'flow_id'`) | 90 проб, назначение достигнуто |
| 8.8.8.8 MDA UDP (до 9 хопов) | только хоп 1 | 314 проб, балансировка на хопах 8–9 |

Почему оригинал теряет хопы за NAT: метка UDP-пробы хранится в контрольной
сумме, а NAT WSL возвращает процитированный заголовок с исходными адресами,
но с контрольной суммой, пересчитанной под внешний адрес. Go-версия
восстанавливает метку по процитированной нагрузке, по поправке на адрес NAT
или по порту источника. Метка ICMP у оригинала стоит в поле IP ID, которое
NAT переписывает.

## 4. Совпадения и отличия в поведении

Совпадает:

- принцип Paris: постоянный flow-id, метка в контрольной сумме UDP, в sequence ICMP и TCP;
- правило остановки MDA (`bound.c` перенесён один в один): n₁..n₅ = 8, 15, 21, 28, 36 при `-B 95,5,128`;
- опции `-a`, `-P`, `-I`, `-T`, `-U`, `-4/-6`, `-f`, `-m`, `-q`, `-w`, `-M`, `-n`, `-p`, `-s`, `-z`, `-t`, `-B`, `-V`.

Отличается:

- порт назначения UDP: оригинал на деле шлёт на 33456, хотя в справке написано
  33457; Go шлёт на 33457 (`-p 33456` даёт полное совпадение путей);
- порт источника: у оригинала 33456, у Go по умолчанию выбирает ОС, MDA меняет порт на каждый поток;
- ожидание ответа по умолчанию: 5 с у оригинала, 3 с у Go;
- Go шлёт пробы одного хопа параллельно и повторяет неотвеченные пробы MDA (`-r`, по умолчанию 2);
- вывод MDA: у оригинала — отладочная решётка потоков и `Lattice`, у Go —
  интерфейсы по хопам с RTT и список связей, плюс JSON (`-j`);
- нет в Go: `-A` (AS-поиск через whois), `--print-ttl`, `-d` (отладка библиотеки);
- есть только в Go: TCP-пробы в MDA, IPv6 для всех протоколов, MPLS-метки из
  ICMP-расширений, JSON, сборка под Windows.

## 5. Ограничения Windows

На Windows TCP-пробы недоступны: система запрещает слать TCP через raw-сокеты.
На loopback Windows не отвечает ICMP port unreachable, поэтому UDP до 127.0.0.1
не завершается; ICMP работает. Промежуточные хопы на Windows требуют прав
администратора и правила брандмауэра для входящих ICMP Time Exceeded. В этой
сессии Windows-версия проверена без прав администратора (видны только ответы
назначения) и в GitHub Actions, где раннеры не пропускают ICMP вообще (даже
`tracert` показывает только `*`). Трассировка через промежуточные хопы на
Windows вживую не подтверждена.
